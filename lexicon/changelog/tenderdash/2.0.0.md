# Tenderdash API Changelog — 2.0.0

> **v2.0.0** vs **v1.8.2**. Platform v5.1.0 pairs with Tenderdash 2.0.0.
> [Tenderdash release](https://github.com/dashpay/tenderdash/releases/tag/v2.0.0) · [Tenderdash upgrade guide](https://github.com/dashpay/tenderdash/blob/v2.0.0/UPGRADING.md#v200) · [Platform upgrade guide](https://github.com/dashpay/platform/releases/tag/v5.1.0#upgrading)

## Platform integration and consensus

| Keyword | Change | Migration | Ref |
|---------|--------|-----------|-----|
| `CONSENSUS_VERSION_2` | Platform protocol 15 schedules Tenderdash consensus version 2 from the next height. The block protocol stays 14, P2P advances to 11, and ABCI advances from 1.4.0 to 1.5.0. | Upgrade Drive and Tenderdash together. Every validator and full node needs Tenderdash 2.0+ before activation. Nodes can upgrade one by one while consensus is at version 0 or 1. | [Platform release](https://github.com/dashpay/platform/releases/tag/v5.1.0#53-tenderdash-consensus-version-2-protocol-15) · [Tenderdash #1572](https://github.com/dashpay/tenderdash/pull/1572) · [version.go](https://github.com/dashpay/tenderdash/blob/v2.0.0/version/version.go) |
| `ProposerHeartbeat`, `RoundSkipVote`, `RoundSkipCertificate` | Consensus version 2 advances an idle proposer's round when its signed heartbeats stop. Drive sets `proposer_heartbeat` to 1 s and `proposer_silence` to 5 s. | Dash Core and file signers support both new signatures. Socket and gRPC remote signers lack them, so their idle rounds can be skipped. `consensus.wal-skip-rounds-to-last` applies only to older consensus versions. | [Tenderdash #1572](https://github.com/dashpay/tenderdash/pull/1572) · [Platform release](https://github.com/dashpay/platform/releases/tag/v5.1.0#53-tenderdash-consensus-version-2-protocol-15) |
| `platform.drive.tenderdash.docker.image` | Dashmate 5.1 migrates managed networks to the `dashpay/tenderdash:2.0` image line. | Follow the full-node Dashmate upgrade for the paired Drive, Core and Tenderdash configuration. The exact Tenderdash release image is `dashpay/tenderdash:2.0.0`. | [Dashmate migration](https://github.com/dashpay/platform/blob/v5.1.0/packages/dashmate/configs/getConfigFileMigrationsFactory.js) · [Tenderdash release artifacts](https://github.com/dashpay/tenderdash/releases/tag/v2.0.0#release-artifacts) |

## ABCI

| Keyword | Change | Migration | Ref |
|---------|--------|-----------|-----|
| `VerifyVoteExtension` | Tenderdash validates commit vote extensions after `ProcessProposal`, before persisting or finalizing the block. An empty `validator_pro_tx_hash` identifies the commit-level call. | Custom applications must add support before upgrading Tenderdash. Compare the ordered threshold-recoverable extensions for the processed block and return `ACCEPT` for valid commits or `REJECT` for mismatches. Drive 5.1 has this handling. The version handshake alone does not establish support. | [Tenderdash #1520](https://github.com/dashpay/tenderdash/pull/1520) · [ABCI upgrade guide](https://github.com/dashpay/tenderdash/blob/v2.0.0/UPGRADING.md#abci-commit-vote-extension-verification) |
| `ProcessProposal`, `ExtendVote` | A height can be processed multiple times, including the same round and block. Tenderdash finalizes only the last processed round. It can call `ExtendVote` on a non-validator after rejecting a commit. | Allow proposal re-execution. Keep `ExtendVote` free of side effects and ensure its threshold-recoverable extensions match what `VerifyVoteExtension` accepts. Avoid `DEFAULT` vote extensions, which are rejected before signing. | [Tenderdash #1520](https://github.com/dashpay/tenderdash/pull/1520) · [Tenderdash #1565](https://github.com/dashpay/tenderdash/pull/1565) |
| `Echo`, `PrepareProposal` | With consensus version 2, an idle proposer sends heartbeats only while its application answers `Echo` within the heartbeat interval. | Keep every backend that handles `PrepareProposal` responsive to `Echo`. | [Tenderdash #1572](https://github.com/dashpay/tenderdash/pull/1572) |

## RPC and configuration

| Keyword | Change | Migration | Ref |
|---------|--------|-----------|-----|
| `broadcast_tx`, `broadcast_tx_sync`, `broadcast_tx_commit` | With `keep-invalid-txs-in-cache` enabled, a resubmitted rejected transaction usually returns the original `CheckTx` result. Pending or committed duplicates still return the duplicate error. Rejected results larger than 2048 bytes also retain the duplicate error. | Check the application response code as well as the JSON-RPC error. | [Tenderdash #1530](https://github.com/dashpay/tenderdash/pull/1530) · [CheckTx upgrade guide](https://github.com/dashpay/tenderdash/blob/v2.0.0/UPGRADING.md#rpc-resubmitting-a-rejected-transaction-returns-its-checktx-result) |
| `broadcast_evidence`, `ErrEvidenceDisabled` | A committed `evidence.max_bytes` of zero disables evidence submission. Platform protocol 15 sets the budget to zero. | Handle the disabled result and check committed consensus parameters before submitting evidence. | [Tenderdash #1547](https://github.com/dashpay/tenderdash/pull/1547) |
| `P2PConfig.ValidateBasic` | Startup validates `[p2p]`. | Keep `incoming-connection-window` ≥ 1 ms, packet payload size > 0, outgoing connections within the effective total, and rates and durations nonnegative. `allowlist-only` needs a persistent or bootstrap peer. | [Tenderdash #1550](https://github.com/dashpay/tenderdash/pull/1550) · [P2P upgrade guide](https://github.com/dashpay/tenderdash/blob/v2.0.0/UPGRADING.md#breaking-the-p2p-config-section-is-now-validated-at-startup) |
| `tx-index.indexer`, `tx-index.psql-conn` | The PostgreSQL event sink is removed. Configuring `psql` as an indexer prevents startup. | Use `kv` or `null`. Remove the obsolete connection key from managed configs. | [Tenderdash #1553](https://github.com/dashpay/tenderdash/pull/1553) |
| `--shutdown-timeout` | The start command defaults to a 30 s shutdown deadline. The container entrypoint waits for Tenderdash after forwarding the signal. | Give the container runtime or supervisor more time than Tenderdash's deadline. Dashmate 5.1 uses a 40 s grace period. | [Tenderdash #1513](https://github.com/dashpay/tenderdash/pull/1513) · [Tenderdash #1607](https://github.com/dashpay/tenderdash/pull/1607) |
| `consensus.peer-query-maj23-sleep-duration` | The interval also paces round-state announcements and vote/commit redelivery. | Account for slower recovery from missed messages when increasing the 2 s default. | [Tenderdash #1598](https://github.com/dashpay/tenderdash/pull/1598) · [Tenderdash #1599](https://github.com/dashpay/tenderdash/pull/1599) · [Tenderdash #1624](https://github.com/dashpay/tenderdash/pull/1624) |
